# Cop 別の一致状況

[README の表](../README.ja.md#cop-別の一致状況)は、2026-10-15 に Ruby 4.0.7 上の RuboCop 1.89.0 と CLI 出力を全項目で比較して再生成しました。索引の参照実装は rubydex 0.4.1 です。**登録 609 Cop、発火 609 Cop、完全一致 609 Cop** です。登録・被覆・正確性を分けて測っています。実プロジェクトの結果は [CONFORMANCE.md](../CONFORMANCE.md) に記録しています。

## 入力と比較

本家 spec の記録には、609 の登録名に対応する 42,594 入力・1,549 設定群があります。両 CLI が最後まで検査できたのは 42,433 入力・1,543 設定群です。本家の spec helper が受け付ける null の `EnforcedStyle` を CLI は拒否するため、６設定群・161 入力は未測定です。追加の索引 174 ケースとファイル名に依存する 2 ケースは、実際の本家 CLI から記録した出力と照合します。各ケースを独立した実行として比較し、索引のケースでは複数のソースファイルも扱います。

設定群ごとの `TargetRubyVersion`、ファイル種別、Regexp・Symbol・バイナリ文字列を含む Ruby の設定型を保ちます。Gemspec・Bundler の入力には必要なファイル種別を使い、`Bundler/GemFilename` と `Lint/RequireRelativeSelfPath` には名前を明示したケースも用意します。`--only` と併用できない３つのディレクティブ Cop は全 Cop で実行し、対象 Cop の記録だけを比較します。

比較前に、空でない対象パス集合の一致と全ファイルの検査完了を確認します。記録は実行ごとの多重集合とし、位置の全項目、length、メッセージ、重大度、修正可否を比較します。重複を捨てず、異なる実行で出た不足と過剰を相殺しません。

通常の fixture テストは、593 Cop に届く記録済み 37,085 ケースを検査する別のゲートです。これが通っても、上の広い CLI 比較の代わりにはなりません。

## 索引の被覆と限界

`Lint/DeprecatedReference`、`Lint/NameTypo`、`Lint/UnusedPrivateMethod` は、`AllCops: UseProjectIndex: true` のとき共有するプロジェクト索引を使います。追加ケースでは、この３つと既存 12 Cop の索引分岐を検査します。継承、クラスの再オープン、可視性、ドキュメント、別ファイルからの参照を含みます。キャッシュの無効化と任意の Bundler gem ソースには別のテストがあります。

測定した入力では **登録数 = 発火数 = 完全一致数 = 609** を達成しました。実コードの `Lint/Syntax` のエラー復帰差や Ruby コーパスの残差は未解決です。構成したケースの一致は、すべてのプログラムでの一致を意味しません。普通のアプリケーションの入力を増やすだけでは、索引が必要な動作や既定無効 Cop の被覆は増えません。

## 既定以外の設定値

設定群ごとの CLI 比較では、記録された設定を既定値へ置き換えません。今回は Regexp タグ、旧式の除外メソッド用パターン、数値パターンのアンカー、メソッド名の許可パターンの差を修正しました。Ruby の真偽判定、名前空間の記法、括弧付き `yield` のハッシュ値省略も本家に合わせています。

YAML の型も直接検査します。Ruby が使う YAML 1.1 の引用符なし `yes`・`no`・`on`・`off` は、引用符付き文字列とは異なります。YAML 1.2 のライターで設定を作り直すと引用符が消え、検査入力そのものが変わることがあるため、該当テストは生の YAML をディスクへ書きます。引用符、明示タグ、アンカー、日本語、不正入力を陽性・陰性の両方で検査します。
